# SenseAudio 音乐与音效生成｜项目复盘 PRD

我负责 SenseAudio 音频创作模块迭代，升级音乐生成的简单模式和专业模式，从零搭建独立的音效生成板块，并完善作品管理与下载。上线 30 天，模块累计沉淀 **1,681 名有效创作用户**。

## 一、项目背景与迭代目标

### 1.1 产品原有状态与主要问题

- **简单模式**　已有音乐描述入口，缺少歌曲／纯音乐、人声等常用选择。
- **专业模式**　能设置的创作参数有限，主题、BPM、调性等需求难以明确表达。
- **音效生成**　当时没有独立的音效创作板块。
- **作品管理**　原入口以收藏为主，缺少音乐、音效分类和生成记录的自动留存。

### 1.2 本次迭代目标

- **降低简单创作门槛**　把作品类型、人声等高频选择前置。
- **提升专业创作控制**　重组主题、歌词、风格与音频参数的填写流程。
- **补齐音效场景**　独立设计描述、时长、多候选试听流程。
- **形成创作与取用闭环**　生成后自动留存，支持分类管理、试听与下载。

## 二、需求优先级与一期范围

一期优先保障“表达需求—生成—试听—取用”，首页沿用已有音乐内容页面。

| 一期重点 | 范围与取舍 |
| --- | --- |
| 音乐生成迭代 | 简单／专业模式、歌词辅助、风格与音频参数。 |
| 音效生成新增 | 独立入口、声音描述、时长、四条候选与试听。 |
| 作品取用 | 我的音乐／我的音效／收藏，保存、重命名、下载、删除。 |
| 计费与权益 | 音乐原价延续，音效计价、次数与并发检查。 |
| 后续推进 | 工作台、片段重修及深度加工，一期明确优先做工作台以外的部分。 |
| 暂不纳入一期 | 参考生成、分轨、加乐器、人声处理、裁剪、分享与社区等。 |

## 三、核心产品方案与交互设计

### 3.1 音乐创作流程优化

简单模式覆盖高频选择。专业模式按照创作决策顺序组织输入。两种模式均为已有功能的升级。

| 模块 | 变化性质 | 本次方案 |
| --- | --- | --- |
| 简单模式 | 已有流程迭代 | 保留简介、AI辅助描述与示例，补充歌曲／纯音乐、自动／男声／女声。 |
| 专业模式 | 已有流程迭代 | 演唱／纯音乐前置，声音独立成区，新增必填主题描述。 |
| 风格选择 | 已有能力迭代 | 排序标签①②③、自定义与风格库，靠前标签影响更大。 |
| 形态分支 | 已有流程迭代 | 演唱与纯音乐使用不同风格列表，纯音乐隐藏歌词和人声字段。 |
| 音频参数 | 新增控制项 | BPM、调性、拍号与MP3／WAV，无明确要求可使用默认参数。 |

#### 音乐创作流程示意

| 简单模式 | 专业模式 |
| --- | --- |
| 描述想要的音乐 | 确定演唱／纯音乐 |
| ↓ | ↓ |
| 选择歌曲／纯音乐 | 填写主题 |
| ↓ | ↓ |
| 歌曲选择自动／男声／女声 | 演唱：歌词＋人声，纯音乐：跳过 |
| ↓ | ↓ |
| 生成并试听 | 选择风格＋设置音频参数 |
| ↓ | ↓ |
| 保存与下载 | 生成 → 试听 → 保存与下载 |

### 3.2 歌词辅助与创作控制

- **已有歌词**　直接输入，模型识别语言，不触发AI参数推荐。
- **从主题生成歌词**　沿用AI生成能力，弹窗内设置语言与韵脚，预览修改后回填。
- **润色已有歌词【新增】**　进入AI润色流程，调整表达后预览、回填。
- **未填写歌词**　由模型根据主题生成，主表单不额外设置语言。

- **中文可选韵脚，英文／韩文不开放**　避免无效设置。
- **AI生成可推荐音频参数，回填后可编辑**　帮助起步，同时保留手动控制。
- **“自动”改为“使用默认参数”**　区分默认值、AI推荐值与手动编辑。

### 3.3 音效生成

新增独立音效板块，以具体声源描述和多候选试听服务短音效创作。

#### 音效生成流程示意

| 独立音效入口 |
| --- |
| 描述声源、动作与材质 |
| ↓ |
| 自动／手动设置时长 |
| ↓ |
| 一次生成四条候选 |
| ↓ |
| 分别试听，挑选合适结果 |
| ↓ |
| 自动进入我的音效 → 下载使用 |

- **输入引导**　描述框＋声源／动作提示。脚步、敲门、雨声、倒水等示例可回填。
- **时长控制**　自动／手动。手动时长为 1–10 秒。
- **生成与挑选**　每次固定四条候选，分别提供播放、波形、时长与下载。
- **结果留存**　自动进入“我的音效”，便于再次查找和使用。

### 3.4 作品管理与下载流程

- **收藏→我的作品【迭代】**　我的音乐、我的音效、收藏三类。保留收藏内容。
- **音效历史【新增】**　收纳生成音效与变体，和音乐作品分开管理。
- **生成结果自动留存【完善】**　支持试听、重命名、下载、删除。
- **下载前须知【新增环节】**　各下载入口统一展示说明，同意并下载才开始取用，取消则返回。

一期作品管理服务于结果取用。工作台的连续修改与版本历史属于后续编辑方案。

## 四、成本测算与商业规则设计

### 4.1 音乐生成的成本与计价

音乐生成沿用按首计价。片段重修还要处理原曲，计算量会受整首作品长度影响，因此后续编辑方案需要同时考虑原曲总长和修改范围。

### 4.2 音效生成的计价方案选择

| 方案 | 用户如何选择 |
| --- | --- |
| 按候选条数收费 | 试听之前就要决定买几条，容易把最后未采用的候选理解为多付的一次尝试。 |
| 统一价格，自选一至四条 | 同样的费用下，用户倾向选满四条，多了一步操作。 |
| 固定四条，统一收费（采用） | 一次付费获得四条候选，用户试听后决定用哪一条。 |

### 4.3 积分与使用权益

将可用次数、积分和同时运行的任务数放在生成前检查。条件满足后开始生成，条件不满足时说明具体原因，让用户能分清需要补足积分还是等待已有任务完成。

## 五、关键产品问题与决策复盘

### 5.1 多语言歌词长度限制

- **问题**　不同语言中，同样的字符数可能对应很不一样的歌词长度。
- **取舍**　采用统一分词计量，兼容混合语言输入。AI 辅助生成时预留长度余量，方便用户继续修改。
- **用户呈现**　编辑时显示长度占比，接近上限时给出精简提示。歌词长度和歌曲实际演唱时长还会受节奏影响。

### 5.2 音乐时长与完整演唱的冲突

- **问题**　长歌词遇上用户手动设定的短时长，可能在唱完前被截断，用户还要为整首生成付费。
- **选择**　最终移除用户侧的「音乐时长」控制项，由系统决定音乐时长，优先保障歌曲完整。音效生成仍支持设置 1–10 秒时长。
- **依据**　用户能够直接判断想听到的歌词和风格，生成前却很难预估这段歌词需要唱多久。

### 5.3 片段重修与作品连续编辑（后续设计）

- **问题**　每次重修产生独立文件，结果与原曲关系分散，连续修改和管理困难。
- **选择**　重修替换回当前歌曲。播放头与修改选区独立。历史自动归属同一作品。
- **依据**　保留满意部分，支持继续修改、试听与恢复历史，减少付费产物丢失。
- **阶段**　工作台属于后续规划。

### 5.4 音效描述与生成预期的偏差

- **问题**　“转场”“轻快”等抽象词未明确声源，容易产生预期偏差。测试另有噪音、电音问题。
- **选择**　引导“物体／场景＋动作＋材质”，提供狗叫、脚步、发动机、倒水等具体示例。
- **依据**　减少可避免的输入歧义，帮助用户表达与挑选。
- **边界**　噪音等音质问题仍需单独处理。

## 七、经验总结与后续迭代规划

### 7.1 本次迭代形成的产品判断

- **模式分工要明确**　简单模式前置高频选择。专业模式按创作顺序组织控制。
- **以成品可用性作为设计取舍的依据**　控制项应帮助用户获得完整、可使用的作品。手动设置音乐时长容易造成歌词截断，因此优先保障作品完整性。
- **多候选也是选择体验**　固定四条统一收费，减少生成前的数量计算。
- **价值延伸到作品取用**　自动留存、分类、试听、下载，后续围绕同一作品组织连续编辑。
