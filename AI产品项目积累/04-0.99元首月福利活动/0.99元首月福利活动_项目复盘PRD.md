# 商汤项目复盘_0.99元首月福利活动

**项目概览**｜SenseAudio面向符合资格的新老用户推出Plus首月0.99元福利，将低价体验与不同套餐的购买、升级及续费规则接通。项目围绕参与资格、分层计价、权益生效、运营触达和交易异常处理展开。结合运营反馈，本次活动是观察阶段增长与拉新的主要来源。

## 一、活动背景与目标

### 1.1 活动背景与主要问题

活动围绕Plus套餐的付费体验展开，需要在降低体验门槛的同时，兼容平台已有用户与套餐体系。设计重点包括以下三方面。

- **首次体验需要更低的进入成本**：以低价试用吸引用户开始使用Plus，将体验意愿转化为实际参与。
- **新老用户的套餐状态不同**：Free、Lite、Plus的购买与生效逻辑不同；尤其是多月Lite，不能简单用一个优惠月替代其剩余有效期。
- **优惠购买需要衔接实际使用**：用户看到入口后，还需理解报价、完成支付并正确获得权益，才能开始或延续使用。

### 1.2 本次活动目标

- **扩大参与和付费体验**：通过0.99元首月优惠覆盖符合资格的新老用户，降低开始体验Plus的成本。
- **促进活跃与使用**：将优惠参与进一步转化为产品使用和Token调用，扩大实际使用规模。
- **保障交易与权益衔接**：明确不同用户的价格、生效时间和原套餐处理方式，减少购买误解与权益损失。

## 二、活动机制与用户分层

### 2.1 核心优惠规则

活动提供Plus月套餐首个活动周期0.99元优惠，不以历史付费记录区分新老用户。活动适用于Web与H5，并复用已有套餐购买、升级和续费逻辑。

- **限享规则**：每个账号、每个已验证手机号限享一次，避免通过切换设备重复参与。
- **优惠范围**：Free／无有效套餐、Lite和Plus用户按各自状态参与；当前生效或待生效Pro／Max／Ultra的用户不可参与。
- **优惠周期**：优惠仅适用于首个活动周期，每个Plus周期按30天计算。多月Lite的后续覆盖周期按标准升级差价补款。
- **到期处理**：活动套餐到期后不自动续费、不自动扣款；继续使用需用户手动按99元购买Plus。

### 2.2 不同用户如何参与

| 用户状态 | 参与方式 | 应付金额 | 权益生效 |
| --- | --- | --- | --- |
| Free／无有效套餐 | 购买1个月Plus | 0.99元 | 立即生效30天 |
| Lite | 升级为覆盖剩余有效期的Plus | 首周期0.99元；后续每周期63元 | 立即生效，整体覆盖原Lite |
| Plus | 同等级续费1个月 | 0.99元 | 当前及已购买的Plus周期结束后顺延30天 |
| 生效或待生效Pro／Max／Ultra | 不可参与 | 不生成活动订单 | 不支持降级参与 |
| 账号或手机号已参与 | 不可重复购买 | 不生成重复优惠订单 | 展示已参与提示 |

活动Banner可被不同状态的用户看到，看到入口并不代表具备购买资格。实际下单前，服务端实时检查账号、手机号、当前套餐和待生效套餐，并向不符合条件的用户说明原因。

## 三、计价方案与权益设计

### 3.1 Lite多周期升级计价

已有升级规则要求：目标套餐有效期不能短于当前套餐剩余有效期。Lite参与活动时，先汇总当前及待生效Lite的全部剩余有效天数，再换算为能够完整覆盖的最少Plus周期数。

需覆盖周期数＝向上取整（Lite剩余有效天数÷30）

应付金额＝0.99＋63×（需覆盖周期数−1）

| Lite剩余有效期 | Plus覆盖周期 | 活动实付 |
| --- | --- | --- |
| 20天 | 1个周期／30天 | 0.99元 |
| 40天 | 2个周期／60天 | 63.99元 |
| 70天 | 3个周期／90天 | 126.99元 |

该规则保留首个周期的优惠，同时让目标Plus覆盖全部剩余Lite有效期。多周期用户的实际支付金额高于0.99元，因此购买页需要同步呈现剩余天数、覆盖周期、计算式和总金额。

### 3.2 不同套餐的权益承接

Lite使用升级逻辑，Plus使用同等级续费逻辑。两类用户都享受一个优惠周期，但权益开始时间和原套餐处理方式不同。

| 场景 | 权益时间线 |
| --- | --- |
| Lite升级 | 剩余Lite有效期 → 支付与目标Plus权益创建成功 → 原Lite整体终止，Plus立即生效并重新计时 |
| Plus续费 | 当前Plus周期 → 已购买的待生效Plus周期 → 本次新增30天Plus周期 |

- **Lite整体覆盖**：升级完成后，全部原Lite周期被目标Plus覆盖，不暂停原套餐，也不在活动Plus到期后自动恢复Lite。
- **Plus顺延生效**：不改变当前周期；本次购买增加一个待生效30天周期，按原续费顺序排队。
- **完整履约后完成参与**：支付成功且活动订单与完整目标权益创建成功后，才覆盖Lite并核销账号、手机号的活动资格。
- **已支付订单持续履约**：活动下线前已支付、但实际生效时间晚于活动下线的订单，仍按约定时间生效。

### 3.3 退款与异常处理

退款由人工客服核验办理。处理时同时核对活动实付、已使用Plus时长和升级前Lite剩余权益，保证退费与权益回收、恢复一致。

- **支付或权益创建失败**：保留原Lite，不占用活动资格；若已错误覆盖，则按支付前记录恢复原权益。涉及退回资金时由人工客服处理。
- **单周期Lite退款**：活动升级实付0.99元全额退回；回收活动Plus，并扣除Plus已使用天数后恢复剩余Lite。
- **多周期Lite退款**：按Plus未使用时长占目标总时长的比例退回活动升级实付款，再按同一规则恢复剩余Lite。
- **资格与后续升级**：用户主动退款后不恢复活动资格；若已进一步升级为Pro／Max／Ultra，按交易链逆序处理，避免只退活动款却保留高级权益。

恢复Lite剩余天数＝max（升级时Lite剩余有效天数−Plus实际使用天数，0）

多周期退款金额＝活动升级实付金额×（目标Plus总天数−Plus实际使用天数）÷目标Plus总天数

例如：Lite剩20天时支付0.99元升级，Plus使用10天后退款，退回0.99元并恢复10天Lite。若升级为90天Plus、实付126.99元，使用10天后退款，则退回112.88元；Lite恢复天数仍按升级时的剩余天数减去10天计算。

## 四、运营触达与购买链路

### 4.1 活动入口与展示策略

活动通过Banner、活动弹窗和系统通知触达用户。入口展示与购买资格分开处理，既保证活动可见，也让不符合资格的用户获得明确解释。

| 入口 | 展示对象 | 作用 |
| --- | --- | --- |
| Banner | 活动期间全量展示 | 提供活动入口；未登录用户可查看详情，购买时需登录 |
| 活动弹窗 | 已登录、符合资格且未购买用户 | 主动提示优惠，并引导进入购买流程 |
| 系统通知 | 已登录、符合资格且未购买用户 | 提供站内活动提醒 |

- **弹窗频次**：符合资格用户每天首次以登录状态进入官网时弹出一次；当天关闭后，再次登录或刷新不重复弹出，次日首次进入可再次展示。
- **停止展示**：购买成功后停止活动弹窗；活动结束后，所有用户均不再弹出。
- **不符合资格的解释**：已参与用户点击Banner后收到限享一次提示；Pro／Max／Ultra用户收到当前套餐不支持降级参与的提示，不开放实际购买入口。

### 4.2 从触达到权益生效的完整流程

| Banner／弹窗等活动入口曝光 |
|  :---:  |
| ↓ |
| **用户点击活动入口** |
| ↓ |
| **登录状态处理与实时资格校验** |
| ↓ |
| **购买页展示报价、周期与权益时间** |
| ↓ |
| **创建订单并完成支付** |
| ↓ |
| **创建完整Plus权益，完成资格核销** |
| ↓ |
| **Free／Lite立即生效；Plus按周期顺延生效** |

未登录分支：点击活动 → 完成登录 → 返回首页 → 再次点击活动入口 → 资格校验与购买页。已登录用户直接按当前账号状态进入校验和购买流程。

支付失败或权益创建失败时，流程返回可解释的异常处理状态；Lite原权益保持不变，未完成有效参与的用户可重新尝试。

### 4.3 购买前的信息说明与链路跟踪

- **价格与周期**：展示实际支付金额和Plus覆盖周期，多月Lite同时展示剩余有效天数及补款计算式。
- **权益时间与覆盖关系**：说明立即或顺延生效、起止时间，以及原Lite整体被覆盖、不自动恢复的处理方式。
- **到期与退款**：说明到期不自动续费，并清晰解释退款由人工客服办理及适用的计算规则。

原PRD的埋点方案按“曝光—点击—登录完成—资格校验—支付页到达—订单创建—支付成功—权益创建成功”跟踪主交易链路，并记录入口来源、用户套餐状态、报价、资格拒绝原因和实际生效时间，便于区分入口参与、支付完成与权益到账。

对Plus用户，购买时间和新增权益生效时间分别记录；后续还可沿用实际生效、活动期升级和活动后原价购买的观察节点，避免把待生效订单理解为当日已经开始使用新权益。

## 五、关键问题与产品取舍

### 5.1 统一优惠与多月Lite实际支付金额的差异

- **问题**：活动以“首月0.99元”吸引参与，但多月Lite必须覆盖全部剩余有效期，实际支付可能为63.99元或126.99元。标题与总报价之间容易产生理解差异。
- **处理方案**：保留首个覆盖周期0.99元，后续周期按63元差价补款；购买前同时展示Lite剩余天数、覆盖周期和实际金额，并解释原套餐被覆盖。
- **决策依据**：兼容已有升级规则，以一条连续交易链承接用户权益，避免优惠月结束后再恢复旧套餐的并行处理。价格说明与权益说明共同帮助用户判断是否购买。

### 5.2 登录回跳与活动来源识别

- **问题**：未登录用户完成登录后，既要继续购买，也要保留其来自活动Banner或弹窗的来源，方便在已有埋点平台中筛选活动购买路径。
- **处理方案**：登录后返回首页，由用户再次点击活动入口，再进入购买页；沿用明确的活动入口事件连接后续交易。
- **决策依据**：设计侧接受登录后多一次点击，以保留活动入口与订单之间可识别的路径。这项取舍涉及交易便捷性与活动来源识别，不能仅以是否到达支付页判断设计目的。

### 5.3 支付成功与权益正确到账

- **问题**：Lite活动升级会终止原套餐。如果支付状态和权益创建状态分别处理，可能出现付费后未得到完整Plus、却已失去原Lite的情况；重复回调也可能造成重复发放或核销。
- **处理方案**：支付和完整目标权益创建成功后，再覆盖原Lite并核销活动资格；失败保留原权益或按支付前记录恢复，并通过账号和手机号限享约束防止重复参与。
- **决策依据**：交易完成需要同时满足收款和权益履约。异常与退款应沿同一订单链处理，让用户付出的金额、实际获得的权益和原套餐状态保持一致。

## 六、活动结果与增长表现

### 6.1 核心结果

在约一个半月的增长观察阶段，平台用户规模、活跃、调用和付费表现均有明显提升。运营人员明确反馈，绝大部分增长和拉新来自本次0.99元活动，因此将其作为这一阶段增长的主要驱动进行复盘。

| 维度 | 已有结果 | 表现 |
| --- | --- | --- |
| 用户规模 | 约1.7万人 → 4.3万人 | 约增加2.6万人 |
| 日活跃用户 | 497人 → 1,185人 | 增加688人，提升约138.4% |
| 产品使用 | Token调用量增长11倍 | 使用规模明显扩大 |
| 付费表现 | 单日付费用户达到477人 | 付费体验规模扩大 |

> 数据说明：用户规模与日活对比采用统计表中7月28日和9月6日的数据；477人对应9月4日的单日付费用户数。Token增长11倍及活动贡献说明来自项目补充信息与运营反馈。表中为全站观察数据，不等同于活动独立订单人数。

### 6.2 结果解读

- **用户规模扩大**：用户规模由约1.7万增至4.3万，结合运营反馈，说明低价活动对本阶段拉新和扩大体验人群发挥了主要作用。
- **增长伴随实际使用**：日活与Token调用同步增长，表明业务表现不仅体现在用户规模上，也体现在用户访问和核心服务使用上。
- **付费体验得到扩大**：单日付费用户达到477人，体现低价入口对付费参与的带动。结合套餐分层、报价说明和权益履约设计，活动将优惠参与承接为可实际使用的Plus权益。

本项目将0.99元的优惠机制落实到新老用户的实际套餐状态，并贯通触达、报价、支付与权益生效。结果部分围绕已有的规模、活跃、调用和付费数据展开，对应“扩大付费体验、促进使用、保障交易衔接”的活动目标。
